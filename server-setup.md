# Подготовка и базовая настройка сервера Active Directory

Документ фиксирует выполненные действия и проверенные параметры домашней лаборатории. Следующий этап — установить роль AD DS и создать лес Active Directory. Не переходите к повышению сервера до контроллера домена, пока не установлены актуальные обновления и не подтверждена описанная ниже сетевая конфигурация.

> Эта конфигурация предназначена для учебной лаборатории. Один контроллер домена является единственной точкой отказа. Для production-среды нужно отдельно проектировать как минимум два контроллера домена, резервное копирование, восстановление и сетевую безопасность.

## Текущая конфигурация

| Компонент | Значение |
| --- | --- |
| Гипервизор | VMware Workstation Pro 17.6.2 |
| Виртуальная машина | `WIN-SERVER` |
| Операционная система | Windows Server 2022 LTSC, версия 21H2, сборка 20348.1249 (образ с обновлениями по ноябрь 2022 года) |
| Будущий DNS-домен AD | `home.arpa` |
| Будущее NetBIOS-имя домена | `HOME` |
| Сеть виртуальной машины | VMware NAT, `VMnet8` |
| Сеть VMnet8 | `192.168.152.0/24` (`255.255.255.0`) |
| IPv4-адрес VMnet8 на хосте | `192.168.152.1` |
| Физический IPv4-адрес хоста | `192.168.100.20` |
| Статический IPv4 сервера | `192.168.152.10` |
| Шлюз NAT | `192.168.152.2` |
| Временный DNS до настройки DNS AD | `192.168.152.2` |
| Диапазон DHCP VMnet8 по данным Virtual Network Editor | `192.168.152.128`–`192.168.152.254` |

`192.168.152.0` — адрес сети, а не адрес устройства. `.1` используется адаптером VMnet8 на хосте, `.2` — шлюзом/DNS NAT. Статический адрес сервера `.10` находится вне указанного DHCP-пула.

## Подготовка VMware и Windows Server

### Установка VMware Workstation

Используется VMware Workstation Pro версии 17.6.2, установочный файл `VMware-workstation-full-17.6.2-24409262`. VMware Workstation установлена на локальном компьютере.

### Установка Windows Server

Виртуальная машина создана в VMware Workstation, установлена Windows Server 2022 LTSC (21H2, build 20348.1249). После входа Windows открывает Server Manager — это обычное поведение Windows Server.

Для VM используется имя `WIN-SERVER`. Проверьте его в **Server Manager → Local Server → Computer name**. Если переименовываете VM, сделайте это до установки AD DS и перезагрузите сервер.

### Пароль локального администратора

Пароль `123` отклоняется политикой сложности и длины. Локальные требования можно посмотреть через **Start → Run → `secpol.msc` → Account Policies → Password Policy**; краткую сводку дает команда `net accounts`. Используйте длинный уникальный пароль/парольную фразу и сохраните его в защищенном хранилище. Не ослабляйте парольную политику ради простого пароля и не записывайте пароль в документацию.

Сообщение о доменной политике не доказывает, что сервер уже присоединен к домену: до создания домена действует локальная политика безопасности.

### VMware Tools и общий буфер обмена

Общий буфер обмена с хостом настроен. Для повторения настройки:

1. В VMware Workstation выберите **VM → Install VMware Tools** (или **Reinstall VMware Tools**).
2. В Windows Server запустите `setup64.exe` с подключенного виртуального DVD-диска VMware Tools и перезагрузите VM после установки.
3. Откройте **VM → Settings → Options → Guest Isolation** и включите **Enable copy and paste**.
4. Проверьте двустороннее копирование обычного текста.

Буфер двусторонний. Не копируйте через него пароли, ключи и другие секреты; отключите функцию, если она больше не нужна.

## Сеть VMware NAT

VM подключена к `VMnet8 (NAT)`. Физический интерфейс компьютера имеет адрес `192.168.100.20`, а VMnet8 создает отдельную подсеть `192.168.152.0/24`. Поэтому IP хоста и гостевой системы отличаются. Изначально VMware выдала гостевой системе адрес из DHCP-пула VMnet8; для контроллера домена он заменен постоянным адресом `192.168.152.10`. VMware транслирует исходящий трафик VM через хост.

Для домашней лаборатории NAT подходит, если контроллер домена и будущая тестовая клиентская VM подключены к одной сети VMnet8. Физические компьютеры локальной сети не получают прямого входящего доступа к VM через NAT. Не публикуйте AD DS, DNS, LDAP, SMB или RDP напрямую в Интернет.

### Проверка текущей адресации

В VMware Workstation проверьте параметры **Edit → Virtual Network Editor → VMnet8** и **DHCP Settings**. В Windows Server откройте PowerShell и выполните:

```powershell
ipconfig /all
Get-NetIPConfiguration -InterfaceAlias "Ethernet0"
Get-NetIPInterface -InterfaceAlias "Ethernet0" -AddressFamily IPv4 |
    Format-Table InterfaceAlias, Dhcp, ConnectionState
```

Проверенные параметры сервера:

| Параметр `Ethernet0` | Проверенное значение |
| --- | --- |
| IPv4-адрес | `192.168.152.10` |
| Маска | `255.255.255.0` (`/24`) |
| DHCP | `Disabled` |
| Шлюз | `192.168.152.2` |
| Временный DNS до настройки AD DNS | `192.168.152.2` |

Серверу назначен статический адрес `192.168.152.10`. В исходной конфигурации DHCP выдавал `192.168.152.128`, но этот адрес находится в динамическом пуле `.128`–`.254` и для постоянного адреса сервера не используется.

### Настройка статического адреса в Windows Server

Адрес уже настроен и проверен. Для повторения настройки используйте консоль VMware, чтобы не потерять доступ к VM при изменении сети:

1. Нажмите `Win+R`, выполните `ncpa.cpl`.
2. Откройте свойства активного адаптера **Ethernet0 → Properties → Internet Protocol Version 4 (TCP/IPv4) → Properties**.
3. Выберите **Use the following IP address** и задайте только после проверки адреса:
   - IP-адрес: `192.168.152.10`;
   - маска: `255.255.255.0`;
   - шлюз: `192.168.152.2`.
4. До настройки DNS-роли AD оставьте временным DNS-сервером `192.168.152.2`.
5. Не меняйте IPv6 без отдельной необходимости.

Для другой VM или сети не копируйте адреса этой лаборатории вслепую. Убедитесь, что адрес свободен, находится в правильной подсети и не входит в DHCP-пул.

### Проверка связи

На сервере проверьте шлюз, DNS и исходящее HTTPS-соединение:

```powershell
ping -4 192.168.152.2
Resolve-DnsName microsoft.com
Test-NetConnection microsoft.com -Port 443
```

На локальном хосте проверьте связь с сервером:

```powershell
ping -4 192.168.152.10
```

Все перечисленные проверки выполнены успешно. Ping с хоста к серверу проходит менее чем за 1 мс.

### Правило брандмауэра для ping с хоста

Windows Defender Firewall может блокировать входящие ICMP Echo Request. Для лабораторной VM создано узкое правило: разрешается только ICMPv4 Echo Request от VMnet8-адаптера хоста (`192.168.152.1`) к серверу (`192.168.152.10`). Брандмауэр целиком не отключался.

Если правило нужно создать повторно, запустите PowerShell на сервере от имени администратора:

```powershell
New-NetFirewallRule `
    -DisplayName "Allow ICMPv4 from VMware host to server" `
    -Direction Inbound `
    -Action Allow `
    -Protocol ICMPv4 `
    -IcmpType 8 `
    -LocalAddress 192.168.152.10 `
    -RemoteAddress 192.168.152.1 `
    -Profile Any
```

Если адрес хоста VMnet8 или сервера изменился, замените соответствующий адрес в правиле. `-Profile Any` здесь используется вместе с ограничением конкретными локальным и удаленным IP-адресами; это не разрешение ping от произвольных устройств.

## DNS перед установкой AD DS

До установки и настройки роли AD DS временным DNS-сервером интерфейса остается NAT DNS `192.168.152.2`. После установки AD DS/DNS и создания домена DNS-клиент контроллера домена должен использовать собственный статический адрес `192.168.152.10`. Внешнее разрешение имен настраивается через DNS forwarders на DNS-сервере AD, а не указанием публичного DNS на интерфейсе контроллера домена.

Будущий тестовый клиент должен быть подключен к той же виртуальной сети VMnet8 и использовать DNS AD-сервера (`192.168.152.10`), чтобы находить домен. Одного доступа клиента в Интернет недостаточно для присоединения к домену.
